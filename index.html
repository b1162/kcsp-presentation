ARCHITECTURE SPECIFICATION

KCSP Modular Monolith Architecture

The KCSP platform is engineered as an enterprise-grade modular monolith with clear domain boundaries, unified TypeScript typings, and zero vendor lock-in.

KCSP/
├── apps/
│   └── web/                   # Next.js 14+ Fullstack Admin Console & APIs
│       ├── (admin)/           # Protected Security Console (Dashboard, Queue, Analytics)
│       ├── t/[token]/         # Opaque Tracking Redirector (HMAC Hashing)
│       └── s/[token]/         # Credential-Safe Simulation & Debrief Engine
└── packages/
    ├── shared/                # Core Zod Schemas, Cryptography & Sanitization
    ├── database/              # Multi-Dialect Prisma (SQLite WAL / PostgreSQL)
    ├── whatsapp/              # Pluggable Provider Abstraction (Mock, WASender, WPPConnect)
    ├── tracking/              # Opaque Token Generation & Event Store
    ├── engine/                # Concurrency Queue, Rate Limiting & Webhook Sync
    └── analytics/             # Department Risk Aggregation & Reporting Engine

WhatsApp Provider Abstraction

Providers implement a clean, decoupled TypeScript interface, allowing instant toggling without modifying business logic:

interface WhatsAppProvider {
  sendMessage(request: SendMessageRequest): Promise;
  getMessageStatus(providerMessageId: string): Promise;
  validateConfiguration(): Promise;
  parseWebhook(payload: unknown, headers?: Record): NormalizedWebhookEvent | null;
  checkSessionStatus?(): Promise<{ connected: boolean; status: string; message?: string }>;
}
ETHICAL SHIELD & PRIVACY

Zero-Credential Safety & GDPR Compliance

1. Zero-Credential Harvesting Guarantee

Collecting actual employee passwords in awareness drills is dangerous, unnecessary, and creates legal liabilities under labor regulations. KCSP strictly solves this:

  • ✓ Client-side DOM scripts intercept all form submissions before network requests are dispatched.
  • ✓ Sensitive values (passwords, PINs, tokens) are purged and replaced with USER_ENTERED_VALUE.
  • ✓ The backend logs only a binary boolean: SIMULATION_INTERACTION = TRUE.

2. HMAC SHA-256 IP/User-Agent Hashing

Under GDPR Article 5 data minimization, raw IP addresses and browser signatures are never stored plaintext. They are salted with a dynamic server secret and hashed via HMAC SHA-256.

3. 1-Click Participant Data Anonymization

When an employee requests right-to-be-forgotten erasure (GDPR Article 17), administrators click Anonymize. Employee names and phones are permanently scrubbed while aggregate statistical risk scores remain intact for historical compliance benchmarking.

DEVOPS & DEPLOYMENT

Docker Compose & Automated Caddy HTTPS

KCSP deploys in a single command using our multi-stage optimized Dockerfile and Caddy reverse proxy handling automatic TLS certificates.

# 1. Clone repository
git clone https://github.com/b1162/kcsp-presentation.git
cd kcsp-presentation

# 2. Configure environment
cp .env.example .env

# 3. Spin up production container
docker compose -f docker-compose.prod.yml up -d --build

# 4. Verify health endpoint
curl http://localhost:3000/api/health
DATABASE TIER

Migrating from SQLite to Managed PostgreSQL

KCSP supports both SQLite in Write-Ahead Logging (WAL) mode and Managed PostgreSQL. Switching to PostgreSQL requires only updating the provider URL in schema.prisma and running Prisma migrations:

# Set PostgreSQL connection string
DATABASE_URL="postgresql://user:password@pg-host:5432/kcsp_db?schema=public"

# Run Prisma migration
npx prisma migrate deploy
